Traps

Three Problems That Give No Useful Error Message

All three were seen on the laboratory machines. None of them prints a message that tells you what is wrong, so learn to recognise them now.

1

Anaconda replaces the system Python. If your prompt begins with (base), Anaconda is active. ROS 2 then fails with No module named 'rclpy._rclpy_pybind11', or colcon build fails with No module named 'ament_package'.

Type conda deactivate in every terminal you use for this laboratory.

2

A new terminal knows nothing. Sourcing a workspace affects only the terminal you typed it in. Every new terminal needs both lines again: first /opt/ros/jazzy/setup.bash, then your own workspace.

The symptom is Package 'my_turtle_circle' not found in a terminal where the package plainly exists.

3

A terminal opened inside a snap application cannot start a window. turtlesim then dies with undefined symbol: __libc_pthread_init. This happens if you open the terminal from inside Visual Studio Code installed as a snap.

Use a normal terminal window for turtlesim.

You asked for 2.000 and you received 2.011. The program keeps publishing until the measured distance passes the target, and by then it has already gone slightly too far. This is overshoot, and every closed-loop controller has it.

BTry

Rotate Ninety Degrees

Type 2, then 90 for the angle, then 0 for counter-clockwise.

Printed when it stops
rotated_related_angle_degree 90.00000250447816 desired_relative_angle_degree 90.0

CBug

Rotate Two Hundred Degrees: the Rotation That Never Finishes

Type 7 to reset, then 2, then 200, then 0. The turtle keeps turning and does not stop. Press Ctrl+C after about ten seconds.

Why

The turtle reports its heading as a number between -π and +π. When it passes +π the number jumps to -π. The program measures how far it has turned with abs(start.theta - current.theta), which can never exceed 180 degrees. The loop waits for 200 and 200 never arrives.

This is the angle wrapping problem from the lecture, and here it is in code that was used to teach this course for two years. Any rotation above 180 degrees hangs. The repair is one line, and you will see it in Week 5.

DTry

Printed on arrival

Notice

This is the difference the lecture is about. Choice A was open loop: drive, count, stop. Choice D was closed loop: measure the distance to the goal, and choose the speed from that measurement. Choice A cannot correct an error. Choice D does nothing else.

Part 3 — What Actually Makes the Robot Move

Three ideas. You need all three to write Part 5, and you need nothing else.

3.1

A Topic Is a Named Channel

Nothing in ROS 2 calls a function on the robot. A program puts a message on a named channel, and any program that is listening to that name receives it. The name for velocity commands in turtlesim is /turtle1/cmd_vel.

  1. $ros2 topic info /turtle1/cmd_vel

    One subscriber: the simulator. No publishers yet, because you have not written one.

    Expected
    Type: geometry_msgs/msg/Twist
Publisher count: 0
Subscription count: 1
3.2

The Message Is Called Twist

  1. $ros2 interface show geometry_msgs/msg/Twist

    Six numbers: three for straight-line speed, three for turning speed.

    Expected
    Vector3  linear
	float64 x
	float64 y
	float64 z
Vector3  angular
	float64 x
	float64 y
	float64 z
Only two of the six do anything

A turtle, like a TurtleBot, drives on two wheels on a flat floor. It can move along the direction it faces, and it can turn. It cannot move sideways. So linear.x and angular.z change the motion, and the other four fields are ignored. This is the nonholonomic constraint from the lecture.

Test it for yourself. The command below is valid, is accepted, produces no error, and does not move the turtle at all.

  1. $ros2 topic pub -r 10 /turtle1/cmd_vel geometry_msgs/msg/Twist '{linear: {y: 2.0}}'

    Watch the turtle for five seconds, then press Ctrl+C. Nothing moved, and nothing reported a problem. The message was correct; the motion is impossible.

3.3

A Control Loop Is a Timer That Publishes

One message is not enough. turtlesim stops the turtle about one second after the last command arrives, so a single message produces one brief movement. To keep a robot moving you must keep publishing. Every node you write in this course has the same shape:

the shape of every node in this coursepseudocode
create a publisher on /turtle1/cmd_vel
create a timer that fires ten times a second
every time the timer fires:
    build a Twist message
    put the speeds into it
    publish it
Keep this number

A robot that publishes linear.x = v and angular.z = ω without changing them drives a circle of radius R = v / ω. You will use v = 2.0 and ω = 1.0 in Part 5, so your circle will have a radius of 2.0. Write that number down now and compare it with what you measure.

Checkpoint
  • You can say what a topic is in one sentence.
  • You know which two fields of a Twist message a differential-drive robot obeys.
  • You know why a node must publish repeatedly and not once.
  • You have predicted the radius of your circle: R = v / ω = 2.0.

Part 5 — Write the Node That Drives a Circle

Thirty lines. Type them; do not paste them. You will remember the structure of a ROS 2 node far better if you have written it once.

5.1

Create the File

  1. $cd ~/ros2_course_ws/src/my_turtle_circle/my_turtle_circle

    The inner folder. If you create the file in the outer one, it will not be installed and ros2 run will not find it.

  2. $gedit circle.py

    Or nano circle.py, or code circle.py. Any editor.

5.2

The Whole Program

~/ros2_course_ws/src/my_turtle_circle/my_turtle_circle/circle.py 30 lines 
import time
import rclpy
from rclpy.node import Node
from rclpy.signals import SignalHandlerOptions
from geometry_msgs.msg import Twist

class Circle(Node):
    def __init__(self):
        super().__init__('circle')
        self.pub = self.create_publisher(Twist, '/turtle1/cmd_vel', 10)
        self.create_timer(0.1, self.send)

    def send(self):
        msg = Twist()
        msg.linear.x = 2.0
        msg.angular.z = 1.0
        self.pub.publish(msg)

def main():
    rclpy.init(signal_handler_options=SignalHandlerOptions.NO)
    node = Circle()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        node.pub.publish(Twist())
        time.sleep(0.3)
    rclpy.shutdown()

if __name__ == '__main__':
    main()
5.3

Line by Line

LineWhat it does
class Circle(Node)Your node inherits from Node. That is what gives it a publisher, a timer and a name in the ROS 2 graph.
super().__init__('circle')Registers the node under the name circle. This is the name ros2 node list will show.
create_publisher(Twist, '/turtle1/cmd_vel', 10)The message type, the topic name, and a queue of 10 messages. The topic name must match exactly, including the leading slash.
create_timer(0.1, self.send)Call send every 0.1 seconds, which is ten times a second. This is the control loop.
msg.linear.x = 2.0Forward speed, in units per second. It must be written 2.0 and not 2. An integer is accepted here and then kills the process later, when the message is published, with a C assertion and no line number. See the last section of this sheet.
msg.angular.z = 1.0Turn rate, in radians per second. Positive turns to the left.
rclpy.spin(node)Hand control to ROS 2 and let it call your timer. Nothing after this line runs until the node is stopped.
SignalHandlerOptions.NOTells ROS 2 not to handle Ctrl+C itself, so Python raises KeyboardInterrupt and your except block runs. Without it, ROS 2 shuts the connection down first and your stop message cannot be sent. That is exactly the failure you saw in Part 2.4.
node.pub.publish(Twist())A Twist with every field left at zero is a full stop. Always stop the robot before you exit.
time.sleep(0.3)Give the stop message time to leave the program. Publishing and then exiting immediately can discard it.

    Put the turtle back in the middle first, at x = y = 5.544.

  2. $ros2 run my_turtle_circle circle

The measurement

Sampled on the laboratory machine over one revolution: x ran from 3.528 to 7.528 and y from 5.544 to 9.544. Half of each span is 2.000.

You predicted R = v / ω = 2.0 / 1.0 = 2.0 in Part 3, before running anything. The model and the robot agree to three decimal places. Change angular.z to 2.0, rebuild, and the radius becomes 1.0. Try it.

One honest detail

turtlesim stops the turtle by itself about one second after the last command, so the turtle would have stopped even without your except block. A real robot does not do this. A TurtleBot 3 keeps the last velocity it was given until something tells it otherwise, which is why the habit of publishing a zero Twist before exiting is worth forming now, in a simulator where a mistake costs nothing.

Part 6 — The Same Node in C++

Optional, and worth the twenty minutes. Recall from Part 1 that ros2_motion_cpp builds but produces no program, because it contains no source file. You are going to give it one, and it will do exactly what your Python node does.

Why do this

The concepts are identical: a node, a publisher, a timer, a Twist. Only the spelling changes. Seeing the same few calls in two languages is the fastest way to learn that ROS 2 is not a Python library. It is a system, and Python is one way to speak to it.

6.1

Write the Source File

  1. $mkdir -p ~/ros2_course_ws/src/ros2_course_packages/src/ros2_motion_cpp/src

    A C++ package keeps its sources in a folder called src/. This one has no such folder yet, which is the clearest possible evidence that it was never finished.

~/ros2_course_ws/src/ros2_course_packages/src/ros2_motion_cpp/src/circle.cpp 33 lines 
#include <chrono>
#include <memory>
#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"

using namespace std::chrono_literals;

class Circle : public rclcpp::Node
{
public:
  Circle() : Node("circle_cpp")
  {
    pub_ = create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    timer_ = create_wall_timer(100ms, [this]() {
      geometry_msgs::msg::Twist msg;
      msg.linear.x = 2.0;
      msg.angular.z = 1.0;
      pub_->publish(msg);
    });
  }

private:
  rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr pub_;
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<Circle>());
  rclcpp::shutdown();
  return 0;
}
Compare the two files

Put this beside circle.py. create_publisher, create_wall_timer, msg.linear.x, spin, shutdown — the same five things in the same order. 100ms is the same interval as 0.1. The node has a different name, circle_cpp, only so that both can run at once and you can see them separately in ros2 node list.

6.2

Tell CMake About It

A Python package is described by setup.py; a C++ package is described by CMakeLists.txt. Open it and add these lines immediately above the line that reads if(BUILD_TESTING). rclcpp and geometry_msgs are already found further up the file, so nothing else needs to change.

~/ros2_course_ws/src/ros2_course_packages/src/ros2_motion_cpp/CMakeLists.txt add 7 lines 
add_executable(circle_cpp src/circle.cpp)
ament_target_dependencies(circle_cpp rclcpp geometry_msgs)

install(TARGETS
  circle_cpp
  DESTINATION lib/${PROJECT_NAME})
What each line does

add_executable compiles the source into a program. ament_target_dependencies links it against the two ROS 2 libraries. install copies the result into the workspace, where ros2 run looks for it. Leave out the install block and the build succeeds while ros2 run reports that nothing was found — a confusing failure that you can now recognise.

    [INFO] [rclcpp]: signal_handler(SIGINT/SIGTERM)
One difference worth noting

The C++ node has no except block, so it publishes no stop message. This is only safe because turtlesim stops the turtle by itself after one second. Writing the C++ equivalent of the Python stop is a good exercise, and it is not straightforward: once spin returns, the connection is already closed.

Checkpoint
  • ros2 pkg executables ros2_motion_cpp lists circle_cpp.
  • The C++ node draws the same circle as the Python one.
  • You can name the five things both versions do, in the same order.

The program dies with no Python traceback:
Assertion `PyFloat_Check(field)' failed.		 You wrote msg.linear.x = 2 instead of 2.0. Twist fields are 64-bit floats. The assignment itself is accepted — the check happens in C when the message is converted for publishing, and it aborts the whole process. There is no line number, which is what makes it hard.

Run the node again with ROS_PYTHON_CHECK_FIELDS=1 ros2 run … and you get a normal Python error at the line that did it: AssertionError: The 'x' field must be of type 'float'. Worth remembering for every message you ever build.
publisher's context is invalid Something was published after rclpy.shutdown(). In your own node, check that the stop message is published inside the except block and before rclpy.shutdown().

Or the speeds were left at zero. Check with ros2 topic echo /turtle1/cmd_vel in another terminal: if nothing appears, your node is not publishing.
The turtle moves for a moment and then stops You published once instead of repeatedly. turtlesim stops the turtle about one second after the last command. You need the timer.
The turtle circles but the radius is wrong Radius is linear.x / angular.z. Check both numbers in your file, and remember to rebuild after changing them — ros2 run executes the installed copy, not the file you just edited.
Two turtles, or two circles at once An earlier node is still running in another terminal. Run ros2 node list; anything you do not recognise is a leftover. Stop it with Ctrl+C in its own terminal.

If the workspace has become confusing, delete the generated directories and build again. Your source code is never touched by this.

    Only src/ matters. Everything else is regenerated.

What to Take Away

  • A workspace is a directory with a src/ in it. Build from the top, and source the result in every terminal.
  • Motion is a message on a topic. No function is called on the robot. You publish a Twist on /turtle1/cmd_vel, and a program that is listening acts on it.
  • A robot obeys two of the six Twist fields. It drives forward and it turns. It cannot move sideways, and asking it to produces no error.
  • One message does not last. The simulator forgets it after about a second, so motion requires a loop that keeps publishing.
  • R = v / ω. You predicted 2.0 from the lecture and measured 2.000 from the robot.
  • Stop the robot before you exit. The simulator hides this mistake. Real hardware does not.

Week 5 takes the last idea further. Your node drives a circle for ever because nothing measures anything. A node that reads /turtle1/pose and chooses its speed from what it reads is a closed-loop controller, and that is the whole of the next laboratory.
