\section{A robot you did not write}

\begin{frame}[fragile]{Before anything else}
  \begin{shells}
$ printenv ROS_DISTRO
$ printenv ROS_DOMAIN_ID
$ ros2 topic list
  \end{shells}

  \vspace{0.4em}
  \small
  Three answers you must see: your distribution name, \textbf{your} assigned domain ID, and a
  list containing \texttt{/parameter\_events} and \texttt{/rosout}.

  \vspace{0.5em}
  \begin{underhood}[If \texttt{ROS\_DISTRO} is empty]
    \footnotesize
    You have not sourced the underlay in this terminal. That is not a broken installation ---
    it is a fresh shell. Source it and try again.
  \end{underhood}

  \vspace{0.4em}
  \centering\footnotesize
  \textbf{Checkpoint 0.} Hand up if any of the three is wrong. Do not go on without it.

\begin{frame}[fragile]{A second terminal, and something to drive it}
  \begin{shells}
$ ros2 run turtlesim turtle_teleop_key
Use arrow keys to move the turtle. 'q' to quit.
  \end{shells}

  \vspace{0.5em}
  \small
  Two processes. Neither was compiled with the other. Neither names the other anywhere in its
  code. Press an arrow key and the turtle moves.

  \vspace{0.6em}
  \begin{underhood}[What just happened]
    \footnotesize
    \texttt{turtle\_teleop\_key} published a \texttt{Twist}. \texttt{turtlesim\_node}
    subscribed to it. They found each other by \textbf{discovery}, because they are on the
    same domain and agreed on a topic name --- and nothing else.
  \end{underhood}

  \vspace{0.3em}
  \centering\footnotesize \textbf{Checkpoint 1.} Everyone has a turtle that moves.
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{Read the contract}
  \begin{shells}
$ ros2 interface show geometry_msgs/msg/Twist
Vector3  linear
Vector3  angular
  \end{shells}

  \vspace{0.5em}
  \small
  The same type you met this morning, printed by the machine rather than by me. Any topic,
  any package, any robot: this command tells you what the message actually contains.

  \vspace{0.6em}
  \begin{inthefield}
    \footnotesize
    \texttt{ros2 interface show} is how you read a vendor's driver when its documentation is
    a PDF from 2019 and the field names have changed. The installed interface definition
    cannot be out of date --- it is what the code was built against.
  \end{inthefield}
\end{frame}

\section{Where your own code lives}

\begin{frame}[fragile]{Workspace, package, module}
  \begin{shells}
ee414_ws/
  src/                    <- YOUR code. Only this is yours.
    ee414_w02_first_node/
  build/                  <- generated. Never edit, never commit.
  install/                <- generated. What actually gets run.
  log/                    <- generated. Build and run logs.
  \end{shells}

  \vspace{0.5em}
  \small
  A \textbf{workspace} is a folder of packages you build together. A \textbf{package} is the
  unit you build, share and install --- one folder, its own dependencies, its own nodes.
  \texttt{turtlesim} is a package; yours will sit beside it.

  \vspace{0.3em}
  \footnotesize
  You edit \texttt{src/}. \texttt{colcon} produces the other three. If you are ever tempted to
  fix something in \texttt{build/}, the answer is in \texttt{src/}.
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{Create the workspace}
  \begin{shells}
$ mkdir -p ~/ee414_ws/src
$ cd ~/ee414_ws
$ colcon build
$ source install/setup.bash
  \end{shells}

  \vspace{0.5em}
  \small
  Building an empty workspace looks pointless. It is not --- it creates \texttt{install/} and
  therefore \texttt{install/setup.bash}, which is the file every future terminal will source.

  \vspace{0.6em}
  \begin{inthefield}
    \footnotesize
    You will use this workspace for the rest of the semester. Every week adds one package to
    \texttt{src/}. Do not create a new workspace per week --- the whole point is that packages
    accumulate and are used together.
  \end{inthefield}
\end{frame}

\section{A publisher}
% ===============================================================

\begin{frame}[fragile]{\texttt{talker.py} --- in \texttt{ee414\_w02\_first\_node/}}
  \begin{pycodes}
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
class Talker(Node):
    def __init__(self):
        super().__init__('talker')
        self.pub = self.create_publisher(String, 'chatter', 10)
        self.create_timer(0.5, self.tick)      # 2 Hz
        self.i = 0
    def tick(self):
        msg = String()
        msg.data = f'hello {self.i}'
        self.pub.publish(msg)
        self.get_logger().info(f'sent: {msg.data}')
        self.i += 1
  \end{pycodes}
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{The four lines that make it runnable}
  \begin{pycodes}
def main():
    rclpy.init()
    rclpy.spin(Talker())
    rclpy.shutdown()
  \end{pycodes}

  \vspace{0.3em}
  \footnotesize
  \begin{center}
  \begin{tabular}{@{}ll@{}}
    \toprule
    \texttt{rclpy.init()} & join the graph \\
    \texttt{rclpy.spin(node)} & hand control to ROS 2: wait for events, call your callbacks \\
    \texttt{rclpy.shutdown()} & leave cleanly \\
    \bottomrule
  \end{tabular}
  \end{center}

  \begin{underhood}[Where the loop went]
    \footnotesize
    \texttt{spin} \emph{is} the loop --- it blocks forever, waking to run timer and subscriber
    callbacks. You never write \texttt{while True} in ROS 2: you declare what happens on each
    event, and \texttt{spin} calls you.
  \end{underhood}
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{Tell the build system the node exists}
  \small In \texttt{setup.py}:

  \begin{pycodes}
entry_points={
    'console_scripts': [
        'talker = ee414_w02_first_node.talker:main',
    ],
},
  \end{pycodes}

  \footnotesize
  Read it right to left: run \texttt{main}, in module
  \texttt{ee414\_w02\_first\_node.talker}, as a command called \texttt{talker}.

  \begin{inthefield}
    \footnotesize
    \textbf{This is where \texttt{turtlesim\_node} came from.} The third token of
    \texttt{ros2 run turtlesim turtlesim\_node} is a name somebody declared in a line exactly
    like the one above. It is also the number-one cause of ``executable not found'' here: a
    typo builds cleanly and fails at run time.
  \end{inthefield}
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{Build it and run it}
  \begin{shells}

$ colcon build --symlink-install
$ source install/setup.bash
$ ros2 run ee414_w02_first_node talker
[INFO] [talker]: sent: hello 0

\section{A subscriber}
% ===============================================================

\begin{frame}[fragile]{\texttt{listener.py}}
  \begin{pycodes}
class Listener(Node):
    def __init__(self):
        super().__init__('listener')
        self.create_subscription(String, 'chatter', self.on_msg, 10)

    def on_msg(self, msg):
        self.get_logger().info(f'got: {msg.data}')
  \end{pycodes}

  \vspace{0.5em}
  \small
  Four things must match the publisher: the \textbf{type} (\texttt{String}), the
  \textbf{topic name} (\texttt{chatter}), the \textbf{QoS} (here, depth 10 --- compatible
  defaults), and the \textbf{domain ID}.

  \vspace{0.4em}
  \footnotesize
  Add a second entry point in \texttt{setup.py}, rebuild, and run it in a third terminal.
\end{frame}

\section{One command instead of three}
% ===============================================================

\begin{frame}[fragile]{Launch files}
  \small
  Three terminals for two nodes. A real robot has fifteen. That does not scale, and you cannot
  reproduce it reliably at 9\,a.m.\ on demo day.

  \begin{pycodes}
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(package='ee414_w02_first_node', executable='talker'),
        Node(package='ee414_w02_first_node', executable='listener'),
    ])
  \end{pycodes}

  \vspace{0.3em}
  \footnotesize
  In \texttt{launch/chatter\_launch.py}, plus one line in \texttt{setup.py} so the folder is
  installed. \textbf{Note:} this \texttt{Node} is a launch description, not the
  \texttt{rclpy} \texttt{Node} you subclassed. Same word, different thing.
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{Run the whole system}
  \begin{shells}
$ colcon build --symlink-install
$ source install/setup.bash
$ ros2 launch ee414_w02_first_node chatter_launch.py
[INFO] [talker-1]: sent: hello 0
[INFO] [listener-2]: got: hello 0
  \end{shells}

  \vspace{0.3em}
  \footnotesize
  One command. Both nodes. \texttt{Ctrl-C} stops both together, and the prefixes tell you
  which node each line came from.

  \begin{inthefield}
    \footnotesize
    Launch files are also where parameters, remappings and namespaces are set --- which is how
    the same node runs twice, on two robots, with different topic names and no code change.
    Week 8 needs this; Week 11 is impossible without it.
  \end{inthefield}
\end{frame}

\section{Breaking it on purpose}
% ===============================================================

\begin{frame}{Five failures --- cause them, read the symptom, fix them}
  \small
  \begin{center}
  \begin{tabular}{@{}p{3.5cm}p{3.6cm}p{3.7cm}@{}}
    \toprule
    \textbf{Do this} & \textbf{Symptom} & \textbf{The lesson} \\
    \midrule
    New terminal, do not source & \texttt{Package not found} & Sourcing is per shell \\[0.3em]
    Misspell the entry point & \texttt{No executable found} & The name is a mapping, not magic \\[0.3em]
    Change the listener's domain ID & Both run. Silence. & Discovery is partitioned \\[0.3em]
    Rename the topic in one node only & Both run. Silence. & Names are the whole contract \\[0.3em]
    Set the listener QoS to \texttt{BEST\_EFFORT}, publisher \texttt{RELIABLE} & Both run. Silence. & QoS must be compatible \\
    \bottomrule
  \end{tabular}
  \end{center}

  \vspace{0.4em}
  \centering\footnotesize
  \textbf{Three of the five look identical from the outside: two healthy nodes, no data.}
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{The diagnostic order that separates them}
  \begin{shells}
$ ros2 node list                         # are both alive?
$ ros2 topic list                        # does the topic exist?
