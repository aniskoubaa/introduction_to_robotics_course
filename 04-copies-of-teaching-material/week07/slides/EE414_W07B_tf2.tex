    \toprule
    \textbf{Link} & \textbf{Published by} & \textbf{Character} \\
    \midrule

    \footnotesize
    A planner needs \emph{smooth} pose: \texttt{odom} $\rightarrow$ \texttt{base\_link}.
    A goal needs \emph{correct} pose: \texttt{map} $\rightarrow$ \texttt{base\_link}. Splitting
    them lets one be smooth and the other be right. This is the design you will rely on in
    Weeks 10 and 11.
  \end{underhood}

\section{Publishing a frame}
% ===============================================================

\begin{frame}[fragile]{A static link, with no code at all}
  \footnotesize Mount a camera 10\,cm forward and 20\,cm up from the robot centre:

  \begin{shells}
$ ros2 run tf2_ros static_transform_publisher \
      --x 0.10 --y 0.0 --z 0.20 \
      --roll 0 --pitch 0 --yaw 0 \
      --frame-id base_link --child-frame-id camera_link
  \end{shells}

  \begin{shells}
$ ros2 run tf2_ros tf2_echo base_link camera_link
  \end{shells}

  \footnotesize
  \textbf{Use the named flags, not bare numbers.} The deprecated positional form orders its
  arguments differently --- the source of many backwards-mounted sensors.

  \centering
  \begin{beamercolorbox}[sep=5pt,center,rounded=true]{palette primary}
    \footnotesize \textbf{Checkpoint 2.} \texttt{camera\_link} appears in \texttt{view\_frames}.
  \end{beamercolorbox}
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{A dynamic link, from a node}
  \begin{pycodes}
from tf2_ros import TransformBroadcaster
from geometry_msgs.msg import TransformStamped

self.br = TransformBroadcaster(self)

def tick(self):
    t = TransformStamped()
    t.header.stamp = self.get_clock().now().to_msg()
    t.header.frame_id = 'base_link'        <- PARENT
    t.child_frame_id  = 'tool_link'        <- CHILD
    t.transform.translation.x = 0.3
    t.transform.rotation.w = 1.0
    self.br.sendTransform(t)
  \end{pycodes}

  \vspace{0.2em}
  \footnotesize
  \texttt{header.frame\_id} is the \textbf{parent}, \texttt{child\_frame\_id} the child.
  Swapping them builds a tree that is inside out --- and it will still run.
\end{frame}

% ---------------------------------------------------------------
\begin{frame}{Two traps in that code}
  \small
  \begin{center}
  \begin{tabular}{@{}p{4.3cm}p{6.5cm}@{}}
    \toprule
    \textbf{The trap} & \textbf{What it costs you} \\
    \midrule
    \texttt{rotation.w} left at its default \texttt{0.0}
      & An all-zero quaternion is not a rotation. Every lookup through this link is garbage,
        and nothing warns you. \textbf{Identity is $w=1$.} \\[0.4em]
    Using \texttt{time.time()} instead of \texttt{get\_clock()}
      & In simulation the clock is not wall time. Your transform is stamped in a different
        era from every other message, and lookups fail. \\
    \bottomrule
  \end{tabular}
  \end{center}

  \vspace{0.7em}
  \centering
  \begin{beamercolorbox}[sep=5pt,center,rounded=true]{palette primary}
    \footnotesize \textbf{Checkpoint 3.} Your \texttt{tool\_link} appears, and
    \texttt{tf2\_echo} shows 0.3\,m forward.
  \end{beamercolorbox}

  \vspace{0.3em}
  \footnotesize
  Try it once with \texttt{w = 0.0} and look at what \texttt{tf2\_echo} reports. Ten seconds,
  and you will never forget it.
\end{frame}

\section{Asking for a transform}
% ===============================================================

\begin{frame}[fragile]{The listener}
  \begin{pycodes}
from tf2_ros import Buffer, TransformListener

self.buffer = Buffer()
self.listener = TransformListener(self.buffer, self)

def tick(self):
    try:
        tf = self.buffer.lookup_transform(
                'odom',          <- TARGET: what frame I want the answer in
                'base_scan',     <- SOURCE: what frame the data is in now
                rclpy.time.Time())
    except TransformException as e:
        self.get_logger().warn(f'no transform yet: {e}')
        return
  \end{pycodes}

  \vspace{0.2em}
  \footnotesize
  \texttt{rclpy.time.Time()} is time zero, which means \textbf{``the latest you have''}.
\end{frame}

% ---------------------------------------------------------------
\begin{frame}{The argument order, which everyone gets wrong once}
  \begin{beamercolorbox}[sep=8pt,center,rounded=true]{palette primary}
    \small \texttt{lookup\_transform(target, source, time)}\\[0.3em]
    returns $T_{\text{target},\,\text{source}}$ --- \textbf{takes source data \emph{to} target}
  \end{beamercolorbox}

  \vspace{0.8em}
  \small
  Lecture A's notation, unchanged: the inner indices cancel. If you have a point in
  \texttt{base\_scan} and want it in \texttt{odom}, you ask for
  \texttt{lookup\_transform('odom', 'base\_scan', t)}.

  \vspace{0.8em}
  \begin{underhood}[Why swapping them is so dangerous]
    \footnotesize
    The reversed call is \textbf{perfectly valid} --- it returns the inverse. No error, no
    warning. Your obstacle simply appears on the wrong side of the robot, and the robot
    steers into it. This is the frame bug promised in Lecture A.
  \end{underhood}
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{Transforming actual data}
  \begin{pycodes}
from tf2_geometry_msgs import do_transform_point
from geometry_msgs.msg import PointStamped

p = PointStamped()
p.header.frame_id = 'base_scan'
p.point.x = 2.1

tf = self.buffer.lookup_transform('odom', 'base_scan', rclpy.time.Time())
p_odom = do_transform_point(p, tf)
  \end{pycodes}

  \vspace{0.4em}
  \small
  \textbf{Do not extract the numbers and do the arithmetic yourself.} The helper handles the
  quaternion correctly, and hand-rolled versions are where sign errors live.

\begin{frame}{Why that checkpoint is the whole week}
  \small
  A point at 2.1\,m in front of the \emph{laser} is a different place in the world every time
  the robot moves. A point in \texttt{odom} stays put.

  \vspace{0.7em}
  \begin{center}
  \begin{tabular}{@{}p{3.3cm}p{7.4cm}@{}}
    \toprule
    Obstacle avoidance (Wk 6) & Works in \texttt{base\_link}: ``is something in front of \emph{me}?'' \\[0.3em]
    Mapping (Wk 10) & Needs \texttt{odom} or \texttt{map}: a wall must stay where it is when the robot moves \\[0.3em]
    Navigation (Wk 11) & Needs \texttt{map}: the goal does not move when the robot does \\
    \bottomrule
  \end{tabular}
  \end{center}

  \vspace{0.6em}
  \centering
  \textbf{Every one of those is the same call with different frame names.} That is why this
  week is worth ninety minutes of your semester.
\end{frame}

\section{The four errors you will meet}
% ===============================================================

\begin{frame}{Cause each one. Read it. Fix it.}
  \footnotesize
  \begin{center}
  \begin{tabular}{@{}p{3.3cm}p{3.6cm}p{3.9cm}@{}}
    \toprule
    \textbf{Do this} & \textbf{The message} & \textbf{The cause} \\
    \midrule
    Look up immediately at start-up
      & ``\texttt{base\_scan} passed to lookupTransform does not exist''
      & The buffer is empty. Nothing is wrong --- you asked too early. \\[0.35em]
    Ask for \texttt{now()} instead of \texttt{Time()}
      & ``requires extrapolation into the future''
      & The transform for that instant has not arrived yet. \\[0.35em]
    Sleep 30\,s, then ask for an old stamp
      & ``requires extrapolation into the past''
      & The buffer discarded it. Your node was too slow. \\[0.35em]
    Publish \texttt{odom} $\rightarrow$ \texttt{base\_link} from a second node
      & No error. The robot twitches.
      & Two parents for one child. \textbf{The dangerous one.} \\
    \bottomrule
  \end{tabular}
  \end{center}

  \vspace{0.4em}
  \centering
  \begin{beamercolorbox}[sep=5pt,center,rounded=true]{palette danger}
    \footnotesize \textbf{Checkpoint 5.} Everyone has seen all four.
  \end{beamercolorbox}
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{The first two are not bugs. Handle them.}
  \begin{pycodes}
try:
    tf = self.buffer.lookup_transform('odom', 'base_scan',
                                      rclpy.time.Time())
except TransformException:
    return          <- normal for the first second. Try again next tick.
  \end{pycodes}

  \vspace{0.4em}
  \small
  A node that starts before the transform publisher \textbf{must} tolerate a few seconds of
  failure. Nodes start in any order --- that is Week 2's no-master design, and this is the
  price of it.

  \vspace{0.4em}
  \begin{inthefield}
    \footnotesize
    \textbf{Never crash on a missing transform, and never retry in a loop inside the callback.}
    Return, and let the next tick try again. A callback never waits --- Week 3's rule, still
    holding.
  \end{inthefield}
\end{frame}

% ---------------------------------------------------------------
\begin{frame}[fragile]{The fourth one, found in one command}
  \begin{shells}
$ ros2 run tf2_tools view_frames
$ ros2 topic info /tf --verbose
Publisher count: 2        <- both publishing odom -> base_link
  \end{shells}

  \vspace{0.5em}
  \small
  Two publishers of the same link produce a transform that flickers between two answers at
  whatever rate they happen to run. The robot twitches, the map smears, and \textbf{nothing
  reports an error}.

  \vspace{0.5em}
  \begin{underhood}[Why a tree makes this findable]
    \footnotesize
    Lecture A: one parent per frame. Because that rule exists, ``this child has two parents''
    is a detectable, meaningful fault. In a general graph it would just be another edge.
  \end{underhood}
\end{frame}
